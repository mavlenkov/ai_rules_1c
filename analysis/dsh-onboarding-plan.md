## Ключевая находка: мост уже есть

- `~/.agents/skills/` — общий слой скиллов (openspec-*, handoff, babysit, create-rule/skill/subagent, shell, …). **DSH читает его нативно** (`<agentsHome>/skills`, rank 500). Именно поэтому в DSH уже видны openspec/handoff/… скиллы.
- ai_rules_1c **уже развёрнут в Codex** (rules + 19 команд + skills + MCP). В DSH его надо переносить заново — но наработки (правила, MCP-каталог, хост `alcor`) переиспользуются напрямую.

## Принцип позиционирования

DSH не заменяет Codex сегодня — это **модель-агностичная обвязка поверх тех же правил и MCP**.
- Codex остаётся рабочей лошадкой для продакшн-1С (gpt-5.6-sol + полный MCP + browser/plugins).
- DSH — «лаборатория»: (1) тест одних и тех же правил на разных моделях (deepseek / glm / …), (2) оркестрация (`workflow`/`goal`/`ralph`), (3) headless-прогоны.

## План по шагам

1. **Не мигрируйте прод.** Пилот на одной задаче в одном проекте.
2. **Выберите модель по умолчанию.** Сейчас default = `deepseek-v4-pro`; Z.AI glm-5.2 доступен. Для 1С-кода сравните обе на одной задаче; модель на субагента можно задавать отдельно (аналог `SUBAGENT_MODEL_*`).
3. **Используйте готовый мост скиллов.** Добавьте в `~/.agents/skills/` недостающие 1С-скиллы (`1c-metadata-manage`, `mcp-1c-tools`, `caveman`) — они станут видны и в DSH, и в остальных инструментах.
4. **Решите вопрос AGENTS.md.** Бюджет инструкций DSH = 64 КБ; `AGENTS.md` (59 КБ) отбрасывается. Сделать тонкий entry-point (<10 КБ) и оставить `content/rules/*.md` on-demand (агент читает их сам).
5. **Подключите 1С MCP** в DSH через `cordis.yml` (плагины `dsh-mcp-client`, транспорт `streamable-http`, хост `alcor`) — это разблокирует цепочку верификации syntaxcheck→check_1c_code→review_1c_code. Учесть имена `mcp__<srv>__<tool>`.
6. **Попробуйте 3 фишки DSH:** `workflow` (fan-out по N файлов), `goal` (долгая цель с автопродлением), `ralph` (цикл свежих агентов).

## Первый эксперимент (прямо сейчас)

Одна реальная 1С-задача, прогоняемая параллельно в Codex и DSH, с одинаковыми правилами и MCP → сравнить результат/цену/скорость. Это и есть «value prop» харнесса.

## Риски / на что не наступить

- DSH `0.1.0-rc.7` — релиз-кандидат, ждать шероховатостей.
- Песочница/аппрувы: в Codex у вас `never` + `full access`; в DSH по умолчанию `workspace-write` + `ask`. Deploy-командам 1С (запись вне workspace, запуск 1cv8) понадобится расширение прав/аппрувов.
- Имена MCP-инструментов в DSH префиксованы (`mcp__1c-syntax-checker-mcp__syntaxcheck`), в правилах — короткие имена.
- `.dev.env` и модельные профили (opus5/sonnet5/…) DSH не читает.
